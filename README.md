# GrepDocs

GrepDocs is a centralized tool to search, browse, and edit documentation across multiple git repositories, with rendered Markdown, full-text search, and direct commits back to source control.

Currently this repository contains the **backend API** (`src/api`, Go). `src/ui` is reserved for a future frontend.

## Prerequisites

- **Go 1.25+** (modular Go toolchain, with `gomod.sh` available)
- **Docker** (for Postgres, Redis, and pgAdmin via `docker-compose.yml` at the repo root)
- **golang-migrate** — install with `go install -tags 'postgres' github.com/golang-migrate/migrate/v4/cmd/migrate@latest`
- **sqlc** — install with `brew install sqlc` or `go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest`
  (if `sqlc`/`migrate` are not found, ensure `$(go env GOPATH)/bin` is on your `PATH`)

## Quick start

```bash
# 1. Start infra (Postgres, Redis, pgAdmin): postgres:5432, redis:6379, pgadmin:8080
make infra-up

# 2. Create your local environment file
cp src/api/.env.example src/api/.env
#    ... then fill in your OAuth client IDs/secrets (see docs/howto/setup-google-auth.md)

# 3. Apply pending database migrations
make migrate-up

# 4. (Re)generate the data-access layer from SQL (needed only on schema/query changes)
make sqlc-generate

# 5. Run the API server (listen on :3000, routes under /api)
make run
```

Check the server is up: <http://localhost:3000/api/ping> should return `pong`.

## How it works

The server loads `src/api/.env` (via godotenv) for configuration. The main session store
is Redis; sessions are plain `Set-Cookie` based. Database access is generated by sqlc from
`schema` migrations + `database/queries.sql` into `src/api/dal/` — never edit generated files
by hand.

`main.go` fatals at startup if `DATABASE_URL` is not set. The database/Redis state is kept in
Docker (see `docker-compose.yml`); credentials come from environment variables or defaults, so
`docker compose up -d` also works without a `.env` file.

## Daily development

| Task                  | Command                                  |
| --------------------- | ---------------------------------------- |
| Start infra           | `make infra-up`                          |
| Stop infra            | `make infra-down`                        |
| Create `.env`         | `make env`                               |
| Run the API           | `make run`                               |
| Build the module      | `make build`                             |
| Apply migrations      | `make migrate-up`                        |
| Rollback migrations   | `make migrate-down`                      |
| New migration         | `make migrate-new NAME=create_foo`       |
| Regenerate DAL / sqlc | `make sqlc-generate`                     |
| Format               | `make fmt` / `make vet`                  |
| Tidy dependencies     | `make tidy`                              |

`go vet` and `go fmt` are the only quality gates: run both before committing.

## Project layout

```
docker-compose.yml     # Postgres + Redis + pgAdmin (repo root)
Makefile               # Wraps the common workflows
src/api/               # Backend API (Go module grepdocs/api)
  main.go              # Entry point, routes mounted under /api
  .env.example         # Template of all required env vars
  database/            # SQL migrations (src/api/database/migrations) + queries.sql
  dal/                 # Generated by sqlc — do not edit by hand
  routers/             # HTTP routes: auth, users, external git accounts
  session/             # Custom Redis-backed session management
  models/              # Domain models
src/ui/                # (empty) — future frontend
docs/                  # Requirements, user stories, how-to guides
```
